# Студентські гуртки та семінари

Лабораторна робота № 2 «Робота з файлами XML». Варіант 22.

Програма відкриває XML-файл зі студентськими гуртками та семінарами, шукає в ньому записи за параметрами і ключовим словом, перетворює знайдене в HTML за допомогою XSL і зберігає результат локально або на Google Drive.

## Дані

Головний вузол для пошуку – `Club`. Структура має два рівні – атрибути самого `Club` і вкладені елементи. Атрибут `Department` є не в усіх записах, тому кількість атрибутів у вузлів `Club` різна (3 або 4).

```xml
<StudentClubs>
  <Club Name="Клуб олімпіадного програмування" Kind="гурток"
        Faculty="Факультет комп'ютерних наук та кібернетики"
        Department="Кафедра теорії та технології програмування">
    <Schedule Day="Вівторок" Time="16:40" />
    <Orientation Course="1" Topic="Алгоритми та структури даних" />
    <Head>Мельник Софія Андріївна</Head>
    <Supervisor>Коваленко Олег Миколайович</Supervisor>
  </Club>
</StudentClubs>
```

| Поле варіанта | Де в XML |
| --- | --- |
| Назва гуртка або семінару | `@Name`, вид у `@Kind` (гурток / семінар) |
| Факультет | `@Faculty` |
| Кафедра | `@Department` (необов'язковий) |
| День і час засідань | `Schedule/@Day`, `Schedule/@Time` |
| Староста | `Head` |
| Орієнтація (курс і тематика) | `Orientation/@Course`, `Orientation/@Topic` |
| ПІП керівника | `Supervisor` |

Приклади лежать у `SampleData`. Там є `clubs.xml` на 12 записів і `clubs.xsl`, який перетворює їх у HTML-таблицю.

## Можливості

- Списки пошуку заповнюються значеннями, які реально є у відкритому файлі.
- Три способи аналізу XML – SAX API (`XmlReader`), DOM API (`XmlDocument` і XPath) та LINQ to XML.
- Запит будується динамічно лише з тих параметрів, які задав користувач. Для DOM згенерований XPath видно над результатами.
- Ключове слово шукається в усіх полях запису.
- Результат оновлюється одразу після зміни будь-якого параметра або способу аналізу.
- XSL-трансформація відфільтрованих даних у HTML.
- XML і XSL відкриваються з диска або з Google Drive. Відфільтрований фрагмент зберігається як XML або HTML туди ж.
- Протокол подій із трьома рівнями — Фільтрація, Трансформація, Збереження.
- Кнопка «Очистити» прибирає результати і параметри пошуку, а перед виходом програма питає «Чи дійсно ви хочете завершити роботу з програмою?».

## Патерни

**Strategy.** Інтерфейс `ISearchStrategy` має три реалізації (`SaxSearchStrategy`, `DomSearchStrategy`, `LinqSearchStrategy`). Контекст `ClubSearcher` викликає ту, яку обрав користувач, і не знає, як саме вона працює.

**Factory Method.** Базовий клас `FragmentSaver` містить спільний код збереження. Він відкриває тимчасовий файл, отримує записувач від фабричного методу `CreateWriter()` і передає готовий файл у сховище. Підкласи лише вирішують, який записувач створити. `XmlFragmentSaver` створює `XmlFragmentWriter`, а `HtmlFragmentSaver` створює `HtmlFragmentWriter` з XSL-трансформацією.

**Singleton.** `EventLogger` існує в одному екземплярі (`EventLogger.Instance`) і дописує події у файл на локальному диску.

Уся логіка зосереджена в `ClubController`. Обробники кнопок інтерфейсу лише зчитують вибране користувачем і показують відповідь.

## Протокол подій

Кожен рядок містить час, рівень і повідомлення.

```
04.11.2026 14:02:22 Фільтрація. Параметри: «Faculty» – Фізичний факультет, «Course» – 1. Спосіб: DOM API. Знайдено: 1
04.11.2026 14:03:10 Трансформація. Збережено у файл clubs_result.html (Google Drive)
04.11.2026 14:03:41 Збереження. Збережено відфільтрований фрагмент у файл /Users/.../Results/clubs_result.xml
```

Шлях до файлу протоколу показано в нижньому рядку вікна.

## Структура

- `StudentClubs/Core` – модель, стратегії пошуку, збереження, протокол і робота з Google Drive
- `StudentClubs/ConsoleTest` – консольний стенд, який перевіряє `Core` без інтерфейсу
- `StudentClubs/Ui` – інтерфейс на .NET MAUI (Mac Catalyst)
- `SampleData` – приклади XML і XSL
- `docs` – UML-діаграми (use-case, діаграма класів, діаграма послідовності)

`Core` не залежить від MAUI. Тому всі три стратегії, збереження і протокол можна перевірити з консолі.

## Запуск

### Консольний стенд

```bash
cd StudentClubs
dotnet run --project ConsoleTest
```

Стенд прогоняє однакові запити через SAX, DOM і LINQ to XML і перевіряє, що всі три способи дають однаковий результат. Інший XML-файл можна передати першим аргументом.

### Графічний інтерфейс (macOS)

```bash
cd StudentClubs
dotnet build Ui/Ui.csproj -f net10.0-maccatalyst
dotnet build Ui/Ui.csproj -f net10.0-maccatalyst -t:Run
```

## Google Drive

Файл `client_secret.json` у репозиторій не потрапляє, тому для роботи з Google Drive потрібен власний OAuth-клієнт.

1. Створити проєкт у [Google Cloud Console](https://console.cloud.google.com/) і ввімкнути **Google Drive API**.
2. На екрані згоди обрати тип **External** і додати свою пошту до **Test users**.
3. Створити облікові дані типу **Desktop app**.
4. Завантажений файл перейменувати на `client_secret.json` і покласти в `StudentClubs/Ui/Resources/Raw/`.

Програма запитує два права. `drive.readonly` потрібне, щоб бачити XML і XSL, завантажені на Drive вручну. `drive.file` дозволяє створювати й оновлювати файли, які зберігає сама програма. Свої файли вона позначає, тому ніколи не перезаписує файл, який користувач завантажив сам.

Дозвіл повертається в програму через локальний порт, тому в `Ui/Platforms/MacCatalyst/Entitlements.plist` увімкнено мережу (клієнт і сервер) та доступ до файлів, які обирає користувач.
